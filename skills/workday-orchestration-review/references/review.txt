# Reviewing Workday orchestrations

Sources: Workday Developer documentation (component references, Handle Errors, Define HTTP Retry
Policies, Concept: XPath Support, runtime limits, Local Disk Sync, Migrating Integration Apps);
the orchestration rules of Arcane Auditor (open-source Workday Extend reviewer, MIT licence,
rules OrchestrationSecurityDomainRule, OrchestrationGlobalErrorHandlerRule,
OrchestrationApiStepErrorHandlerRule, OrchestrationBranchOnConditionsNestingRule,
OrchestratePreferExplicitDefaultAccessor, OrchestrationVerboseBooleanCheckRule); structure of 163
exported orchestrations in Workday's WorkdayDeveloperProgram repository. Retrieved 2026-10-02.

## 1. Getting the exported definition

- Developer Site > Apps > app > related actions > Download Source → ZIP containing
  `*.orchestration` and `*.suborchestration` files (also used for migration between accounts).
- Local Disk Sync (Chromium browser): Open from Local Folder keeps a local copy in sync with
  Orchestration Builder.
- The files are generated by Orchestration Builder. Changes are made in Orchestration Builder,
  not by editing the files.

## 2. File format

One JSON document, usually on a single line, made of nested {"_type": ..., "_value": ...} pairs:
- Root: {"flowVersion": "...", "_type": "Flow", "_value": {...}}.
- _value.name: orchestration name. _value.type._value: flow type —
  .maya.FlowSync (Synchronous), .maya.FlowAsync (Asynchronous),
  .maya.FlowBusinessProcessTriggered (Business Process), .maya.IntegrationFrameworkTrigger
  (Integration System), .maya.FlowSubflow (suborchestration); .Mixed.MixedFlow appears once,
  undocumented.
- _value.start / _value.end: StartBasic/EndSync (Sync), StartAsync (Async), StartBusinessProcess
  (BP), StartIntegrationFrameworkTrigger (IS), StartSubflow/EndSubflow (suborchestration);
  EndEmptyMaya ends Async, BP and IS flows.
- _value.nodes: the steps. Each node has name (Reference Name), isDisabled, errorHandler
  (_value null = no local handler), and type-specific fields. Expressions sit in
  {"_type": ["Expr", T], "_value": {"source": {"_value": "<expression text>"}}}.
- _value.errorHandler: the global error handler (_value null = none). Handler strategy values:
  PropagateError, ConditionalOutputs, GlobalErrorHandler.
- _value.securityDomains: list or null.
- _value.resources.fileLikeResources: inline resources such as Create JSON templates
  (@PLACEHOLDER@ values).
- _value.credentials: e.g. ApplicationSystemUser (ISU) with a username expression.
- defaultWorkdayCredentialRef: default Workday credential; node auth is WorkdayCredentialRef
  (named credential) or AccessTokenFromInitiatingUser.
- retryConfigs: maxTotalRetries, successResponseCodeRanges, defaultBackOff, retryPolicies
  (StatusCodeCondition, HeaderCondition, RetryAfterHeaderInterval).
- Node timeouts: connectTimeoutMs, responseTimeoutMs, overallTimeoutMs.

## 4. Review checklist

Severity ACTION = fix before production; ADVICE = recommended.

Structure and security
- [ACTION] Sync and Async orchestrations define security domains (securityDomains not null).
  Business Process, Integration System and suborchestrations don't support them.
- [ACTION] Sync, Async, Business Process and Integration System orchestrations have a global error
  handler containing a Log step — for Integration System an Add Integration Message step.
- [ACTION] Every API step has its own error handler containing Log (or Add Integration Message in
  IS), including steps inside loops, branches and groups.
- [ACTION] Every API step detects HTTP failure: a retry policy with a success range, or an
  explicit responseStatusCode / isSoapFault check. Without either, non-2xx responses pass silently.
- [ADVICE] Branch on Conditions nested at most 3 levels; extract deeper logic to a
  suborchestration.
- [ADVICE] Steps disabled for debugging (isDisabled true) are intentional.
- [ADVICE] Step count well below 300; orchestrations per app below 150.

Expressions
- [ADVICE] Prefer default-capable accessors: replace booleanAtJsonPath, numberAtJsonPath,
  objectAtJsonPath, stringAtJsonPath, bigDecimalAtXPath, booleanAtXPath, dateAtXPath,
  dateTimeAtXPath, numberAtXPath, stringAtXPath, xmlString, zonedDateTimeAtXPath with their
  ...WithDefault / ...OrEmptyString variants, or validate first when the value is mandatory.
  (bigDecimalAtJsonPath has no default variant.)
- [ADVICE] No redundant conditional wrappers such as `if (cond) true else false`.
- [ADVICE] No logic based on processingError.message() / rawMessage() (logging only).
- [ADVICE] No toString() on large documents; iterate instead.
- [ADVICE] Launch parameter and attribute names used in lp.* / intsys.* / attrstore.* exist and
  match exactly.

Placement and limits
- [ACTION] No Send Workday RaaS Request, Trigger Business Process, Trigger Integration or Trigger
  PDF Generation inside a Join Loop; no RaaS or Trigger Business Process inside a
  suborchestration; Log to File, Add Integration Message, Trigger Integration and Trigger PDF
  Generation only in Integration System orchestrations.
- [ADVICE] Long work split by checkpoints so each process stays under 60 min (45 before
  production); Sync flows called from pages finish within 25 s.
- [ADVICE] "Enable Wait for Long Running Response" and Force Sequential Processing used only when
  needed (they serialise loops).
- [ADVICE] Join Loop instead of nested loops with searches; joining dataset ≤ 500 MB.

Credentials and data protection
- [ACTION] No literal secrets in expressions, headers, query parameters or text templates;
  credentials come from Settings > Credentials / Cred Store.
- [ADVICE] OAuth uses Cred Store Reference in production; ISU only where needed and with role
  checks; Trigger Business Process uses access tokens rather than ISU.
- [ADVICE] Log messages contain no personal data.
- [ADVICE] Store Document in IS sets Attach document to integration event when the file must
  appear on the event; expiry set deliberately.

## 5. Observations about Workday's own samples

Many Workday sample orchestrations don't meet this checklist (for example 55 of 67 synchronous and
19 of 31 integration-system samples have no global error handler). Treat samples as illustrations
of components, not as quality standards.

## 6. Reporting format

For each finding: severity, rule, location (orchestration name > step Reference Name, or the
node path), what is wrong, the fix in Orchestration Builder terms. Order: ACTION first, then
ADVICE. End with what was checked and what could not be checked (for example tenant-side
configuration, credentials' actual permissions).
The same orchestration rules are implemented by the open-source Arcane Auditor tool, which
developers can run on their own machine; this agent doesn't run tools.
